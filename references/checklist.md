# Checklist anti-hallucination (avant livraison)

Passer cette checklist avant chaque réponse livrée ou chaque fin d'étape.

## Ancrage

- [ ] Chaque fait sur le code a-t-il été **lu** dans le dépôt (pas déduit
      de mémoire) ?
- [ ] Chaque fait externe (API, version, comportement) a-t-il une source
      (doc officielle, code installé) ?
- [ ] Aucun **nom inventé** : fonction, fichier, chemin, commande,
      variable, paquet ?
- [ ] Aucune **URL, date, version ou statistique** inventée ?

## Code

- [ ] Le code a-t-il été **relu** après écriture ?
- [ ] Tests / build / lint ont-ils été exécutés (sinon : marquer
      *« non testé »*) ?
- [ ] Les affirmations *« ça marche »* sont-elles **vérifiées** ?

## Focus

- [ ] Suis-je encore sur la **tâche initiale** (reformulée au départ) ?
- [ ] Ai-je détourné la demande vers un annexe non demandé ?
- [ ] En cas d'ambiguïté : ai-je **demandé** au lieu de choisir en
      silence ?

## Honnêteté

- [ ] Les incertitudes sont-elles **marquées** (*« à confirmer »*,
      *« non vérifié »*) ?
- [ ] Ai-je distingué ce qui est **lu/sourcé** de ce qui est
      **supposé** ?
- [ ] Préférerais-je retirer une affirmation douteuse plutôt que la
      laisser ?

Si une case reste non cochée sans raison : corriger avant de livrer.
